# Quickstart: Multiple Organization Trees

1. Keep `company_os_multi_tree_v1` disabled.
2. Run domain, API, authorization, routing, and migration tests.
3. Run migration dry run and resolve orphan/duplicate/cycle findings.
4. Apply only in non-production and verify the legacy projection.
5. Enable for Admin, HR, and one pilot root leader.
6. Create a secondary tree and share one employee across both trees.
7. Change the primary membership and verify only a newly submitted request changes route.
8. Disable the flag and verify the Phase 005 single-tree route still works.

Required full checks before handoff are the repository checks in `AGENTS.md`.

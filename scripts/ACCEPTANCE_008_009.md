# تشغيل قبول Phase 008 و009

هذا المشغّل مخصص لبيئة غير إنتاجية فقط. يرفض تلقائياً نطاقات ZaWolf
الإنتاجية وأي عنوان لا يحمل دلالة واضحة مثل `staging` أو `test`.

## فحص الصلاحيات المحلي الحقيقي

يشغّل الأمر التالي Firebase Auth وFirestore Emulator، ويبذر هويات اختبار
آمنة، ثم يشغّل خادم ZaWolf الفعلي ويختبر 39 طلب API عبر ثمانية أدوار بدون
كتابة ناجحة:

```bash
cd scripts
npm run accept-008-009-emulator
```

يُحفظ الدليل في
`scripts/acceptance/008-009-emulator-matrix-evidence.json`. لا يستخدم الاختبار
مشروع الإنتاج أو مفتاح خدمة. ولا يُعد بديلاً عن تجربة هاتفين وموقعين فعليين
المطلوبة قبل التفعيل الافتراضي.

### آخر دليل محلي

في 2026-08-26 نجح تشغيل المحاكي للدليل الحالي: ثمانية أدوار، موقعان، 39 طلب
API، صفر تجاوز للصلاحيات، وصفر كتابة اختبارية. نتيجة التشغيل محفوظة في ملف
الدليل المذكور أعلاه. هذه نتيجة محلية معزولة وليست دليلاً على نشر Hostinger أو
قبول هاتفين فعليين.

### تحقق واجهة العميل المرتبط

في 2026-08-26 نجحت اختبارات Flutter المركزة للمواقع المتعددة، الأشجار
المتعددة، اختيار الخريطة على الويب، سياسة الانصراف، مؤشرات المبيعات، وأدوات
المطوّر. هذا يثبت العقود والواجهات محلياً فقط؛ لا يثبت اتصال API الفعلي أو
نتائج جهازين حقيقيين.

### فحص الخدمة المنشورة للقراءة فقط

في 2026-08-26 أعاد `https://notification.zawolf.ai/health` حالة `ok=true`،
وكانت خدمة Google Sheets وGoogle Drive وGoogle Workspace مهيّأة، كما أكمل
آخر تزامن للمبيعات مطابقة ثمانية مستخدمين. كما أعاد فحص CORS لمسار
`/company-os/organization/units` رأس `X-Operation-Id` ضمن الرؤوس المسموحة
لـ Firebase Hosting. هذا لا يفعّل أعلام الإطلاق ولا يعد قبولاً وظيفياً
للحسابات الحقيقية.

### حالة الإصدار الحي وبوابة المتابعة

نُشرت واجهة Firebase Hosting في 2026-08-26 بالإصدار
`d4a60a6461339e23` إلى مشروع `zawolf-hr-system-60317`. تؤكد رؤوس الاستجابة
أن `index.html` لا يخزن مؤقتاً. الفحص التالي للخادم يثبت أن الخدمة متصلة،
لكنه لا يساوي قبولاً فعلياً على أجهزة الموظفين:

| البند | الحالة التي ظهرت من `/health` | الإجراء المطلوب |
| --- | --- | --- |
| شجرتا المنظمة والمواقع المتعددة | مفعّلتان في إصدار المالك | مراقبة أول شجرة إضافية وأول موقعين فعليين؛ التراجع بتعطيل العلم فقط، من دون حذف بيانات. |
| تقارير HR داخل Google Sheets | غير مهيأة (`googleHrReports.configured=false`) | ضبط `GOOGLE_HR_REPORTS_SPREADSHEET_ID` لحساب خدمة غير إنتاجي أولاً، ثم اختبار إنشاء تقرير يومي/أسبوعي/شهري. |
| ميزات Phase 007 | لا يوجد علم مهيأ (`phase007.configuredFlags=[]`) | لا تعتبر واجهات 007 مفعلة. فعّل شريحة تجربة محدودة فقط بعد اجتياز مصفوفة الدور. |
| الانصراف التلقائي | متوقف افتراضياً (`checkoutEnabled=false`) | يبقى كذلك حتى ينجح اختبار جهازين حقيقيين للاستثناءات: الإذن الزمني، استراحة 13:00–14:00، مهلة العودة، وإعادة الدخول. |
| CORS لمسارات Company OS | سليم حالياً ويقبل `X-Operation-Id` | إذا ظهرت الرسالة في الواجهة، استخدم إصدار الويب الأحدث/امسح Service Worker ثم سجّل رقم الإصدار والطلب الفاشل؛ لا تغيّر إعداد CORS دون دليل. |
| مؤشرات المبيعات | آخر مزامنة طابقت 8 مستخدمين | التحقق من ظهور نفس الفترة في واجهة الويب بحساب تجريبي قبل تعيين KPI أو استخدام نتيجة الرواتب. |
| تقرير التدقيق في Workspace | آخر خطأ تشخيصي `forbidden` | تحقّق أن المستخدم الذي ينشئ التقرير Super Admin أو IT Manager، وأن حساب الخدمة يملك مجلد التقارير؛ لا تعدّل صلاحيات Google لكل المستخدمين. |

هذه البوابة تمنع الخلط بين «الكود والاختبارات المحلية سليمة» و«تم قبول
السلوك الفعلي على الأجهزة». لا تغيّر قواعد Firestore ضمن خطوة التحقق هذه.

## 1. بروفة الترحيل الآمنة

```bash
cd scripts
ZAWOLF_008_009_ACCEPTANCE_BUILD_ID=008-009-rehearsal-1 \
ZAWOLF_008_009_ACCEPTANCE_MODE=migration \
ZAWOLF_008_009_MIGRATION_FIXTURE=acceptance/008-009-migration.fixture.example.json \
npm run accept-008-009 > acceptance/008-009-migration-evidence.json
```

لا تكتب هذه الخطوة إلى Firestore. وهي تثبت أن الخطتين حتميتان، قابلتان لإعادة
التشغيل، وأن التراجع يتم بتعطيل العلم دون حذف بيانات.

## 2. مصفوفة الصلاحيات الحقيقية

انسخ `release-008-009-acceptance.env.example` إلى ملف خاص خارج Git، واستبدل
الرموز بحسابات Firebase غير الإنتاجية الفعلية للأدوار الثمانية. ثم صدّر القيم
وشغّل:

```bash
cd scripts
ZAWOLF_008_009_ACCEPTANCE_MODE=matrix npm run accept-008-009 \
  > acceptance/008-009-role-matrix-evidence.json
```

المشغّل يستخدم طلبات قراءة وطلبات mutation ناقصة عمداً. نجاح طلب mutation
يعتبر فشلاً؛ لذلك لا ينشئ شجرة أو إسناداً أثناء فحص الصلاحيات.

## 3. تجربة الشجرة الثانوية والموقعين

بعد تنفيذ السيناريوهات على موظفين وجهازين وموقعين حقيقيين، انسخ قالب
`acceptance/008-009-pilot-observations.example.json` واكتب النتائج بأسماء
مستعارة فقط. لا تضع اسماً أو بريداً أو رقم هاتف أو UID في ملف الدليل.

```bash
cd scripts
ZAWOLF_008_009_ACCEPTANCE_MODE=pilot \
ZAWOLF_008_009_ACCEPTANCE_ALLOW_PILOT=true \
npm run accept-008-009 > acceptance/008-009-pilot-evidence.json
```

يفشل القبول ما لم يجد الخادم الشجرة الثانوية والموقعين النشطين، وما لم تنجح
حالات الحضور اليدوي، انقطاع الشبكة، الدخول التلقائي، منع التكرار، الإسناد
القديم، الموقع غير النشط، والخروج عن النطاق ضمن حدود الزمن والقراءات.

## 4. إثبات التراجع

عطّل العلمين لجمهور التجربة ثم شغّل:

```bash
cd scripts
ZAWOLF_008_009_ACCEPTANCE_MODE=rollback npm run accept-008-009 \
  > acceptance/008-009-rollback-evidence.json
```

لا تغيّر جمهور أي علم أو قواعد Firestore إلا بعد مراجعة ملفات الأدلة الأربعة
وموافقة المالك الصريحة. لا تحفظ ملفات الرموز أو ملفات الأدلة التي تحمل بيانات
فعلية داخل Git.
